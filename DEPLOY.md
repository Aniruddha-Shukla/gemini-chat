# Deploying: MongoDB Atlas + Render + Vercel

| Piece | Host | Free tier |
|---|---|---|
| Database | MongoDB Atlas | M0 cluster, 512 MB |
| API (`server/`) | Render | Web service; sleeps after 15 min idle, ~1 min to wake |
| Frontend (`client/`) | Vercel | Hobby (personal, non-commercial) |

Order matters because each piece needs a URL from the one before it:
**GitHub → Atlas → Render → Vercel → back to Render** (to allow the Vercel URL). About 20 minutes.

The repo already contains the config each host needs:
- `render.yaml`: Render Blueprint (build/start commands, health check, env vars, auto-generated `JWT_SECRET`)
- `client/vercel.json`: Vercel install/build commands and the SPA rewrite (so refreshing `/chat/<id>` doesn't 404)

---

## 1. Push the code to GitHub

```bash
cd /path/to/GEMINI
git init -b main
git add .
git status                      # make sure NO .env files are listed (only .env.example)
git commit -m "Initial commit"
gh repo create gemini-chat --private --source=. --push
```

No `gh` CLI? Create an empty private repo named `gemini-chat` on github.com, then:

```bash
git remote add origin https://github.com/<your-username>/gemini-chat.git
git push -u origin main
```

## 2. MongoDB Atlas (database)

1. Sign up at https://www.mongodb.com/cloud/atlas/register.
2. **Create a cluster** → **Free (M0)** → provider **AWS**, region **Oregon (us-west-2)** (same region as the Render service, for low latency) → Create.
3. **Database user**: Security → *Database Access* → *Add New Database User*
   - Authentication: Password. Username: `gemini-chat`
   - Click *Autogenerate Secure Password* and **copy it**
   - Built-in role: *Read and write to any database* → *Add User*
4. **Network access**: Security → *Network Access* → *Add IP Address* → *Allow Access from Anywhere* (`0.0.0.0/0`) → Confirm.
   Render's free tier has no fixed outbound IP, so Atlas has to accept any IP; the strong password is what protects it.
5. **Connection string**: *Database* → *Connect* → *Drivers* → copy the string. It looks like:
   ```
   mongodb+srv://gemini-chat:<db_password>@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
   ```
   Make two edits: put your password in place of `<db_password>`, and add the database name `gemini-chat` right after `.net/`:
   ```
   mongodb+srv://gemini-chat:YOUR_PASSWORD@cluster0.abcde.mongodb.net/gemini-chat?retryWrites=true&w=majority&appName=Cluster0
   ```
   (If the password contains `@ : / ? #`, URL-encode those characters. Autogenerated passwords don't.)

**Optional check:** put this string in `MONGODB_URI` in your local `server/.env` and run `npm run dev:server`. You should see `MongoDB connected: …mongodb.net`. Put the local value back afterwards if you want to keep developing against Docker.

## 3. Render (API)

1. Sign up at https://render.com with **GitHub**.
2. Dashboard → **New +** → **Blueprint** → connect your GitHub account if asked, give Render access to the `gemini-chat` repo, and select it.
3. Blueprint name: `gemini-chat`. Render reads `render.yaml` and shows one service, **gemini-chat-api**. It asks for three values:
   | Key | Value |
   |---|---|
   | `MONGODB_URI` | The Atlas string from step 2.5 |
   | `GEMINI_API_KEY` | Your key from https://aistudio.google.com/apikey |
   | `CLIENT_URL` | `http://localhost:5173` for now (you'll set the real Vercel URL in step 5) |
4. Click **Deploy Blueprint** and wait for the log to show *Your service is live*. The first build takes about 2 minutes.
5. Copy the service URL from the top of the service page, e.g. `https://gemini-chat-api.onrender.com`.
   Check it: open `https://gemini-chat-api.onrender.com/api/health` in a browser. You should see `{"status":"ok"}`.

## 4. Vercel (frontend)

1. Sign up at https://vercel.com with **GitHub**.
2. **Add New…** → **Project** → **Import** the `gemini-chat` repo (click *Adjust GitHub App Permissions* if it isn't listed).
3. On the configure screen:
   - **Project Name**: `gemini-chat` (this becomes `gemini-chat.vercel.app` if the name is free)
   - **Root Directory**: click *Edit* → choose **`client`** → Continue. *(This step matters most: without it the build fails.)*
   - **Framework Preset**: Vite (detected automatically). Leave Build and Install settings alone; `client/vercel.json` sets them.
   - **Environment Variables**: add
     - Key `VITE_API_URL`
     - Value: your Render URL + `/api`, e.g. `https://gemini-chat-api.onrender.com/api` (no trailing slash)
4. Click **Deploy**. When it finishes, go to the project's overview and copy the **production domain**, e.g. `https://gemini-chat.vercel.app`.
   Use this short domain, not the long per-deployment URL (`gemini-chat-abc123-yourname.vercel.app`).

## 5. Let the frontend talk to the API (CORS)

1. Render → **gemini-chat-api** → **Environment**.
2. Edit `CLIENT_URL` → your Vercel production domain exactly, e.g. `https://gemini-chat.vercel.app` (https, no trailing slash).
   To allow more than one origin (e.g. a custom domain), separate them with commas.
3. **Save, rebuild, and deploy**, then wait until it's live.

## 6. Try it

Open your Vercel URL → **Sign up** → send a message.

If the API has been idle, the first request takes up to a minute while Render wakes it up. The app pings the API as soon as the page loads to start that early.

## Updating the app later

- **Code changes**: `git push`. Vercel rebuilds on every push to `main`. Render rebuilds only when `server/`, `package.json` or `package-lock.json` change.
- **Render env vars** (key, model, CORS): Environment → edit → *Save and deploy*.
- **`VITE_API_URL` on Vercel** is baked into the build. After changing it: Deployments → ⋯ on the latest → **Redeploy**.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Browser console: *blocked by CORS policy* | `CLIENT_URL` on Render doesn't exactly match the page's origin (check https, no trailing slash, right subdomain). Also shows up when the API is crashing; check Render → Logs. |
| UI says *Cannot reach the server* | API asleep, deploying, or crashed (Render → Logs), or `VITE_API_URL` is wrong (needs `https://` and must end in `/api`; redeploy Vercel after fixing). |
| Render log: *Could not connect to MongoDB* | Atlas Network Access is missing `0.0.0.0/0`, the password in the URI is wrong, or the database user wasn't created. |
| Vercel build fails / *vite: not found* | Root Directory isn't set to `client` (Project → Settings → Build & Deployment). |
| Refreshing `/chat/...` gives a Vercel 404 | Same: Root Directory must be `client` so `client/vercel.json` is used. |
| *Gemini is not configured yet* | `GEMINI_API_KEY` missing on Render. |
| *The model … was not found* | Set `GEMINI_MODEL` on Render to `gemini-flash-latest` (or another current model id). |
| Branch preview URLs on Vercel get CORS errors | Expected: only origins in `CLIENT_URL` are allowed. Add a preview origin there (comma-separated) if you need it. |

## Good to know

- **Secrets** live only in the Render and Vercel dashboards. `.env` files are git-ignored and never pushed. `JWT_SECRET` on Render is generated by Render and differs from your local one, so local logins don't carry over (that's intended).
- **Gemini free tier** has rate limits, and Google's terms for unpaid usage allow prompts to be used to improve their products. Enable billing on the key if that matters for your users.
- **Upgrading** Render to a paid instance removes the sleep/wake delay. Nothing in the code needs to change.
